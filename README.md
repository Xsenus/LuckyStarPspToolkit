# Lucky Star PSP Translation Toolkit

Версия **0.11.0** — инженерная предварительная версия C#/.NET 9 для анализа и подготовки переводов Lucky Star: Ryouou Gakuen Outousai Portable и экспериментального формата Net Idol Meister.

**В 0.11.0 C# впервые реально скомпилирован и исполнен в доступной диагностической среде.**
Все шесть сборок прошли Roslyn/C#13; выполнены 9 групп Core-тестов, 29 групп Formats-тестов,
Roslyn-аудит документации и 11 шагов сквозного синтетического демо. Исправлены ошибки,
которые прежние лексические проверки не находили.

**Граница проверки:** этот запуск использует reference assemblies и runtime PowerShell
(.NET 11 preview), а НЕ целевой .NET 9 SDK/MSBuild. Windows EXE, штатный publish,
GitHub Actions и реальная игра пока не проверены. Файлы `sc.cpk`, `lt.bin`, ISO и
исходный customer archive в этой среде отсутствуют. Ни `EXE`, ни неподходящие DLL
из диагностической среды в поставку не включены.

Точные команды, среда и логи: [отчёт 0.11.0](docs/TEST_REPORT_RU.md).

## Начать здесь

Полная инструкция: [docs/USAGE_RU.md](docs/USAGE_RU.md). Сценарий встречи с заказчиком: [docs/CUSTOMER_DEMO_RU.md](docs/CUSTOMER_DEMO_RU.md).

Для сборки нужны .NET **9 SDK**, Python **3.11+** (в CI используется 3.13) и библиотеки инструментов проверки:

```powershell
python -m pip install -r validation/requirements.txt
.\build.cmd --rids win-x64
```

По умолчанию `build.cmd` / `./build.sh` создают оба пакета: `win-x64,linux-x64`. Для Linux:

```bash
python3 -m pip install -r validation/requirements.txt
./build.sh --rids linux-x64
```

Сборка последовательно проверяет документацию, генерирует синтетические эталоны, запускает статические проверки, компилирует solution, запускает оба C# self-test проекта и Roslyn-аудит документации, затем публикует и проверяет нативный CLI. Только после успеха формируются ZIP и SHA-256 в `artifacts/releases/0.11.0/`.

**Если один шаг не прошёл, релиз не считается готовым.** Подробные логи: `artifacts/build-logs/<run-id>/`. Предыдущая успешная папка релиза сохраняется при ошибке до финального продвижения новой папки.

## Что уже есть в коде

Единый CLI объединяет чтение SFO/PRX/ELF, расшифровку поддерживаемого EBOOT, ревизионные патчи VWF/heap, CPK/ITOC/@UTF/CRILAYLA, экспорт/импорт сценариев через JSON, LT/BDF и ISO9660. Неизвестные или неподтверждённые состояния отвергаются. Это описание реализованных модулей, а не утверждение о выполненной приёмке реальных игр.

```text
lsptool version
lsptool --help
lsptool self-test
lsptool collect-assets game.iso lucky-star-assets.zip --include-optional
lsptool cpk-verify sc.cpk
```

Полный перечень: [CLI reference](docs/CLI_REFERENCE.md).

## Изменения 0.11.0

Исправлены 11 диагностик компилятора в коде и тестах; XML-комментарии перенесены
перед атрибутами, устранены пропуски, найденные настоящим Roslyn. Снят `NoWarn 1591`.
Исправлено уничтожение уже записанных результатов при сбое очистки резервных копий.
Пересекающиеся пути групповой записи отклоняются до изменения файловой системы.

AES-CMAC теперь обрабатывает сообщения блоками 64 КиБ с двумя очищаемыми pooled-буферами,
а не создаёт копии целого сообщения. Проверены 81 независимо рассчитанный тег и
границы блоков/чанков. `@UTF` получил совокупный лимит ячеек и выделений для
повторяющихся бинарных значений; 512 мутаций заголовков обработаны без необработанных исключений.

Исправлен реальный блокировавший релиз дефект демо: исходный пустой русский шрифт
должен возвращать `2` (incomplete), а не `0`. Все 11 шагов демо теперь прошли.
Подробности: [RELEASE_NOTES_0.11.0_RU.md](docs/RELEASE_NOTES_0.11.0_RU.md).

## Публикация на GitHub

[Инструкция GitHub](docs/GITHUB_PUBLISH_RU.md). Обычный push запускает проверку и сборку пакетов в Windows/Linux. Push тега `v0.11.0`, совпадающего с `VERSION`, после успешной проверки обеих платформ создаёт **draft prerelease** с ZIP и SHA-256. Перевод не объявляется завершённым автоматически.

## Состав

`Core` — криптография, SFO, EBOOT и профиль; `Formats` — архивы, сценарии, карты/шрифты, ISO; `Cli` — команды; `tests` — автономные C#-тесты; `tools/...Documentation` — Roslyn-аудит; `scripts` и `validation` — сборка, независимые эталоны и проверки; `docs` — инструкции и спецификации.

В исходном комплекте нет игровых образов, оригинальных ресурсов, файлов шрифтов, готовых EXE/DLL и заранее выдуманных результатов C#-тестов. Бинарные синтетические эталоны, включая шрифтовые, создаются локально генератором и не коммитятся.

### Ограничения карты глифов в 0.11.0

Помимо байтового лимита, входной карте задаются предел 1 000 000 UTF-16 единиц и 128 единиц на одну метку глифа. Количество строк и длина меток проверяются до `Split`/построения trie; это предотвращает непропорциональное выделение памяти для огромной строки или миллионов пустых строк. Пределы настраиваются в `FileLimits`. Это защитные ограничения, а не измеренная гарантия расхода RAM или времени.
