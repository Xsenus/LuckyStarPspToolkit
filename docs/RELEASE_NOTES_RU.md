# 0.19.0 — изоляция MFA-нагрузки и безопасные конкурентные сессии

Продолжение v0.18.0 / 46a2b65e1e5a4bed3a53928df0a2bbcff1f9c198.
Прежние файлы и Git-история сохранены. Схема лицензий, issuer и протокол клиента не менялись.

- PBKDF2 вынесен из общей блокировки сессий; 600000 итераций и проверка MFA сохранены.
- Независимые одновременные полосы login и recent-MFA, без очереди паролей.
- HTTP admission 2/2/8: медленный login не занимает все обработчики владельца.
- Раздельные login/reauth лимиты также в Nginx-шаблоне; обе конфигурации проверены локальным HTTPS-тестом.
- Проверка cookie/CSRF до тела запроса и повторно после его чтения.
- Повторная проверка сессии, таймаута, отмены и shutdown перед расходованием фактора.
- Общие recovery/TOTP не принимаются дважды даже при login и reauth одновременно.
- Reauth-бюджет привязан к сессии; анонимный login его не расходует, смена IP не сбрасывает.
- Исправлена эксклюзивная граница 300 секунд свежего MFA.
- React объясняет причины отказа без автоматического повтора учётных данных.
- 25 новых C# групп (24 детерминированные и одна реальная HTTP-группа) и 8 Node tests.
- Новый документ ADMIN_AUTH_CONCURRENCY_RU.md и публичный cross-version harness.

В исторической поставке 0.19.0 нативный SDK9/Windows/publish, production TLS и реальные игровые ресурсы не были проверены. В 0.19.1 build/CI/HTTPS/client/restart проверки выполнены; реальные игровые ресурсы по-прежнему отсутствуют.
Фактический статус текущей поставки: TEST_REPORT_RU.md и reports/validation-summary.json.
