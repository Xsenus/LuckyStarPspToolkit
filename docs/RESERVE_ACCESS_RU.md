# Резервный доступ без связи · 0.16.0

## Что это такое

Это подписанный сервером **временный полный доступ к рабочим командам продукта** для одной
уже активированной установки. Нет вечного универсального пароля, локального флага «снять защиту»
или мастер-ключа. Новая/неактивированная установка сначала активируется онлайн обычным ключом.

По умолчанию резервная система выключена и обычные лицензии сохраняют строгий онлайн-режим.
Установка не становится автономной только потому, что основная лицензия бессрочная.
Владелец отдельно включает резервную политику и выдаёт разрешение нужной установке.

## Три разных вида полномочий

| Вид | Для чего | Срок |
|---|---|---|
| Обычный access key | Активация основного права пользования ПО | Часы, дни, годы или бессрочно |
| Reserve grant + подписанный LSPR1 | Работа активированной установки без сервера | 1–168 часов после последнего успешного обновления |
| Recovery code админки | Заменяет только TOTP при входе владельца с паролем | Одно использование; не активирует программу |

У бессрочной основной лицензии с reserve=168 часов все функции работают, но не позднее семи дней
после последнего подписанного обновления. Если к концу срока связи нет — команда блокируется.
У основной лицензии на шесть часов резерв никогда не продлевает доступ на семь дней:
ValidUntil = min(текущее серверное время + окно резерва, окончание основной лицензии).

## Включить в React-панели

1. Выдайте обычную лицензию и попросите пользователя активировать клиент.
2. Откройте «Резервный доступ» и включите резервную систему. При необходимости подтвердите MFA.
3. Выберите активную лицензию и её установку, задайте окно от 1 до 168 часов и причину выдачи.
4. Сохраните/передайте показанную команду с UUID разрешения. UUID не секретный ключ подписи:
   чужая установка не может использовать этот допуск.

Команда на компьютере клиента при доступном сервере:

```powershell
.\lsptool.exe license reserve-enable --id UUID_ВЫДАННОГО_ДОПУСКА
.\lsptool.exe license status
```

После этого перед рабочими командами приложение сначала проверяет основную лицензию онлайн.
При успехе оно обновляет резерв; во время длительных команд проверки повторяются.
При транспортной недоступности разрешён переход только на **ранее выданный, неистёкший** LSPR1.
Каждый запрос подписан установкой и содержит свежий одноразовый challenge/nonce.
Самостоятельная работа не двигает срок вперёд. Максимум 604800 секунд проверяется и сервером,
и клиентом независимо от значения в JSON.

Локально отказаться от резервного режима:

```powershell
.\lsptool.exe license reserve-disable
```

Онлайн-лицензия остаётся действующей. Для повторного включения снова требуется сервер.
Повторная активация другой лицензии удаляет старый локальный резерв, не наследуя чужой допуск.

## Отозвать или выключить

«Отозвать» у конкретного reserve grant прекращает его новые обновления навсегда.
«Отключить резервную систему» прекращает все новые обновления и меняет поколение policy epoch.
Повторное включение не оживляет старые grants: для них нужно новое явное разрешение.
Повтор запроса с тем же ID идемпотентен, случайное повторное нажатие не продлевает срок дважды.

**Без связи нельзя мгновенно передать отзыв на компьютер.** У отключённого от сети клиента
ранее подписанный допуск может работать до собственного срока, максимум семь дней.
При следующем успешном контакте клиент узнаёт об отключении/отзыве и сохраняет запрет локально.
После этого намеренное отключение Интернета не возвращает старый допуск.
Приостановка/отзыв/истечение основной лицензии или сброс установки также не должны маскироваться
резервом после получения серверного отказа. Простая HTTP-ошибка доступности не считается отзывом.

Резерв — компромисс доступности и задержки отзыва. Для быстрого прекращения тестового доступа
оставляйте обычный онлайн-режим либо выдавайте резерв на 1–6 часов, а не 168.

## Локальное время и состояние

Проверяются подпись издателя, продукт, основная лицензия, UUID резерва, host binding и ключ установки.
`reserve.json` в закрытом каталоге установки содержит внутренний authority-token и checkpoint,
подписанный локальным ключом установки; исходный access key там не хранится.
Внутри процесса используется монотонный таймер. На границе процессов сохраняются отметки времени;
обнаруженный откат календаря блокирует офлайн-запуск до онлайн-обновления.
Округление checkpoint выполняется в безопасную сторону: частые короткие перезапуски не возвращают
отброшенные доли секунды. Возможна потеря менее секунды допуска на такой checkpoint.

Это не аппаратная аттестация. Полное клонирование/откат всей VM, контроль ОС/локального ключа и
модификация EXE остаются угрозами. Абсолютной защиты от владельца машины и вечной невзламываемости нет.
Согласованный откат всего сервера требует отдельной инфраструктуры резервирования/аудита.

## Сбой уже выполняемой команды

Сторож проверяет истечение времени независимо от ожидающего сетевого запроса.
По истечении допуска процесс останавливается с кодом 77. Исходные игры не удаляются,
но возможны незавершённые временные файлы/группы результатов. Проверяйте отчёт сборки перед использованием.

## Диагностика

| Код | Значение |
|---|---|
| RESERVE_DISABLED | Общая политика выключена |
| RESERVE_REVOKED | Grant отозван или относится к старому поколению |
| RESERVE_UNKNOWN | UUID не найден у текущего издателя |
| RESERVE_BINDING | Не та установка/лицензия/nonce |
| RESERVE_EXPIRED | Подписанный срок закончился |
| RESERVE_CLOCK | Обнаружен откат местного времени, нужно онлайн-обновление |
| RESERVE_CACHE | Повреждено локальное подписанное состояние |
| RESERVE_UNAVAILABLE | Резерв не включён или локально заблокирован |

Полноценный offline activation при уже упавшем сервере, аппаратный TPM-anchor и HA authority
в этой итерации не реализованы. Подготовьте нужным пользователям резерв заранее.
