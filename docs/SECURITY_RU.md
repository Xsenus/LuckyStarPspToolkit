# Безопасность обработки бинарных файлов

## Входные данные

Все ISO, бинарные файлы, ZIP, JSON, BDF и пути считаются недоверенными. Парсеры проверяют границы до чтения и используют лимиты на количество элементов, размер записей и общий объём.

## ISO9660

- образ открывается только на чтение и обрабатывается потоково;
- проверяются `CD001`, descriptor version, terminator и file structure version;
- little-endian и big-endian копии чисел обязаны совпадать;
- multi-volume, нестандартный размер блока и interleaving отклоняются;
- каждый extent должен помещаться и в объявленный том, и в физический файл;
- контролируются глубина каталогов, число записей, число экстентов, размер одного каталога и общий объём каталожных данных;
- повторная ссылка на тот же каталог считается циклом;
- дубли путей без учёта регистра отклоняются;
- multi-extent последовательность должна иметь совместимые имена и флаги;
- полный JSON-листинг оценивается до сериализации и ограничивается по размеру;
- объект `Iso9660Entry` нельзя подменить записью из другого экземпляра образа.

## Обратная сборка ISO

- исходный образ и результат обязаны быть разными файлами;
- исходный ISO дважды хэшируется: до операции и во время потокового копирования;
- манифест принимает только относительные файлы внутри собственного каталога;
- SHA-256 и размер каждого replacement могут быть закреплены в манифесте и в любом случае проверяются до и во время копирования;
- SHA-256/размер исходной цели могут быть обязательными preconditions;
- одна ISO-запись и один локальный файл нельзя использовать в операции повторно;
- replacement payload добавляется в новый extent; существующие данные и каталоги не перемещаются;
- обновляются одновременно little-endian и big-endian копии LBA, длины и размера тома;
- исходный префикс staged ISO побайтно сравнивается с источником вне разрешённых полей PVD/directory records;
- staged ISO повторно разбирается до commit;
- проверяются число записей, метаданные всех нецелевых путей и SHA-256 каждой замены;
- multi-extent цели, extended attributes, supplementary/partition/неизвестные descriptors отклоняются;
- запись результата атомарна и восстанавливает прежний output при сбое;
- JSON-отчёту запрещено совпадать с ISO, манифестом или любым replacement-файлом.

## Сбор игровых ресурсов

- извлекаются только заранее определённые PSP-пути;
- все файлы копируются по extent и одновременно хэшируются SHA-256;
- общий размер выбранных файлов ограничен;
- выходной ZIP создаётся во временном файле и фиксируется атомарно;
- встроенный манифест не содержит абсолютных локальных путей;
- timestamps ZIP стабильны, поэтому одинаковый вход и параметры дают воспроизводимый архив;
- неполный комплект явно отмечается и возвращает код `2`.

Собранный архив всё равно содержит оригинальные игровые данные и не должен публиковаться.

## ZIP и файловая система

- входной ZIP читается потоково без автоматической распаковки;
- абсолютные пути, drive paths, `..` и дубли отклоняются;
- ограничиваются количество, размер и степень сжатия записей;
- защищённые выходные пути не могут проходить через symbolic link или reparse point;
- вход, выход, предпросмотр и JSON-отчёт не могут совпадать;
- отчёт не может размещаться внутри защищённого workspace.

## EBOOT, VWF и script heap

- зашифрованный EBOOT принимается только при точном SHA-256 подтверждённой ревизии `ULJM05752`;
- PRX Type 2 проверяется по SHA-1, KIRK header CMAC и payload CMAC до получения ELF;
- профиль VWF содержит 133 точные пары `expected/replacement`; любое третье значение блокирует операцию;
- частично применённый профиль распознаётся только после восстановления всех известных слов и совпадения канонического SHA-256;
- таблица размеров сценариев должна иметь ненулевые размеры и корректную накопительную сумму для всех 11 строк;
- динамические изменения таблицы нормализуются только для проверки происхождения и не маскируют изменения за пределами разрешённой области;
- script heap кодируется только проверенной парой `lui a0` / `addiu a0,a0`;
- требуемый heap равен максимуму исходного `0x236000` и крупнейшего сценария;
- `%hi/%lo` рассчитывается с учётом знакового immediate; результат декодируется обратно и сверяется;
- объединение VWF и size-plan разрешено только с точным чистым исходным ELF;
- после объединения выполняется побайтовая проверка: size-plan может менять только таблицу и две heap-инструкции;
- итог повторно проходит проверку 133 слов, таблицы, heap и канонической линии происхождения;
- выход — расшифрованный ELF; инструмент не утверждает, что он является заново подписанным retail PRX.

## Атомарные операции

Связанные результаты сначала создаются во временных файлах. Старые цели переводятся в `.bak`, новые фиксируются, а при ошибке изменения откатываются. Потоковая запись ISO-файлов и ZIP использует тот же fail-safe механизм.

## PSP PRX и EBOOT

- Type-2 PRX проходит историческую SHA-1-проверку оболочки;
- проверяются AES-CMAC заголовка и payload KIRK CMD1;
- ELF выдаётся для патчирования только после подтверждения ревизии;
- SHA-256 идентифицирует полный файл;
- перед записью таблицы размеров проверяются старые значения и накопительные суммы;
- повторное применение плана блокируется.

SHA-1 используется только потому, что является частью формата PSP; новая идентификация выполняется SHA-256.

## CPK, сценарии и JSON

- `@UTF`, ITOC и CRILAYLA проверяют размеры, типы и выравнивание;
- новый сценарий и CPK повторно разбираются;
- незаменённые записи сравниваются побайтно;
- CPK, карта, сценарий и source-текст защищены хэшами;
- неизвестные JSON-поля отклоняются;
- структурные глифы нельзя подставить как перевод;
- переход внутрь изменяемой строки приводит к отказу.

## Шрифты и BDF

- `lt.bin` должен иметь размер, согласованный с числом записей, и правильную checksum;
- карта ограничена диапазоном до `0xFEFE`;
- BDF ограничен размером файла, числом глифов, размером `BBX` и суммой bitmap-пикселей;
- дубли Unicode-кодов и структурных полей отклоняются;
- каждая строка bitmap проверяется как точное hexadecimal-значение;
- обрезка пикселей запрещена по умолчанию;
- отсутствующая русская буква делает сборку неполной;
- неизвестные биты, служебный байт и padding исходного `lt.bin` сохраняются;
- PNG ограничен по ширине, высоте и общему числу пикселей;
- toolkit не включает сторонний шрифт.

## Зависимости

- runtime NuGet-зависимостей нет;
- сетевые запросы из C# отсутствуют;
- внешние EXE не запускаются;
- код игры никогда не исполняется;
- оригинальные игровые файлы не включаются в репозиторий и релиз.

## Осознанные ограничения

- реальная совместимость `sc.cpk` и `lt.bin` подтверждается только после получения этих файлов;
- ISO9660 поддерживается, CSO пока нет;
- NIM остаётся непроверенным профилем;
- корректность таблицы, script heap и VWF подтверждается статически, но окончательная достаточность памяти и поведения рендера проверяется только запуском игры;
- генерация кириллицы и VWF-патч должны применяться совместно с соответствующей картой глифов;
- финальная приёмка требует PPSSPP и настоящей PSP.

## Публикация репозитория

Перед созданием архива или Git-тега выполняется:

```bash
python validation/audit_repository.py
python validation/validate_customer_baseline.py
```

`audit_repository.py` анализирует только отслеживаемое Git-дерево и отклоняет:

- известные шаблоны приватных ключей и access tokens;
- неподтверждённые EXE, DLL, PDB и native libraries;
- игровые `.bin`, `.cpk`, `.iso`, `.pmf`, `.sfo` вне synthetic fixture directory;
- любой файл, SHA-256 которого совпадает с ранее переданным файлом заказчика.

Синтетические fixtures разрешены только в `tests/LuckyStarPspToolkit.Formats.SelfTests/Fixtures` и должны воспроизводиться `scripts/reference_oracle.py`.

`validate_customer_baseline.py` не читает приватный архив. Он проверяет, что сохранённые результаты предыдущей реальной обработки по-прежнему совпадают с текущими revision/VWF-профилями. В отчёте это явно обозначается как `rawCustomerArchiveReprocessed: false`.

GitHub workflow получает минимальные permissions: обычный CI — только `contents: read`, создание GitHub Release — отдельный job с `contents: write` после успешной сборки и smoke tests обеих платформ.
