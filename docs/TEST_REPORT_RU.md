## Что покрывает Licensing SelfTests

Проверены сроки в часах/сутках/календарных годах, календарная граница високосного года,
отсчёт от выдачи/первой активации, точная граница истечения, бессрочная запись с коротким
исполняемым допуском, крайний срок новых активаций, лимит установок, 12 конкурентных
активаций одного слота, невозможность повторно начать пробный период, suspend/resume,
необратимый revoke, идемпотентное продление, перевод в permanent, сброс устройства.

Проверены одноразовые challenge, replay/expiry, заполнение и очистка ограниченного кэша,
подпись владения ключом установки, привязка ответа к nonce/product/issuer/device,
изменённые подписи и claims, строгий JSON/base64url, повреждение HMAC-снимка базы,
неверный пароль, потерянная база, эксклюзивный писатель, сохранение после перезапуска,
откат времени относительно сохранённого состояния, отсутствие сырых ключей в базе/аудите.
Проверка действующей установки не переписывает базу на каждом heartbeat.

Отдельно выполнены настоящие loopback HTTP-запросы, изоляция owner API, истечение
монотонного допуска и обнаружение отзыва долгоживущей сессией. Новые файлы/каталоги
на Linux проверены на ограниченные права. Windows CNG и Windows ACL скомпилированы,
но их исполнение требует Windows; Linux-тест не объявляется такой проверкой.

## Сквозной процессный сценарий

1. Неконфигурированный CLI блокирует работу с кодом 77.
2. Создаётся отдельный временный издатель, затем отдельный тестовый клиент.
3. Проверяются отсутствие активации и неправильный ключ.
4. Через настоящий owner CLI/HTTP выдаётся часовой ключ; повтор выдачи не дублирует лицензию.
5. Ключ активирует настоящий процесс CLI, проходят online status и self-test.
6. Исходное 11-шаговое демо CPK/JSON/шрифта/ISO выполняется через лицензионный шлюз.
7. Suspend блокирует следующий запуск, resume восстанавливает его.
8. Продление выполняется через owner API, revoke блокирует запуск.
9. Выдаётся и активируется бессрочная лицензия.
10. Остановка сервера блокирует запуск; после перезапуска сохранённая активация действует.
11. Экспортируется журнал владельца.

Итого **24 зарегистрированных шага**, включая ожидаемые отказы 77, а не только успешные команды.
Тестовые секреты/исходники временного издателя удаляются; копии отчётов редактируются так,
чтобы в поставку не попали значения ключей, owner bearer и приватные PKCS#8.
Логи: `reports/licensing-process/`. Исходный synthetic demo — не запуск PSP-игры.

## Эксплуатационные ограничения

Строгий online gate не гарантирует защиту от модифицированного EXE, root/administrator,
клонирования VM, передачи исходников и старой незащищённой версии. Нет HSM/TPM-аттестации,
HA-кластера, автоматической ротации приватного подписанта, биллинга/веб-кабинета.
Отзыв обнаруживается при следующем обмене/истечении короткого допуска, а не мгновенно.
Бессрочность лицензии не означает автономность от сервера. Подробно: `LICENSE_SECURITY_RU.md`.

## Воспроизведение

```powershell
# Сначала owner tools и настройка собственного HTTPS-издателя:
py -3 scripts/build_license_owner.py --rids linux-x64,win-x64

# Потом клиентский релиз с ТОЛЬКО публичным профилем:
.\build.cmd --rids win-x64 --license-trust C:\LspOwner\client-trust.json

# Диагностика на заранее подготовленном доверенном альтернативном host:
py -3 scripts/verify_roslyn.py --pwsh <полный-путь-к-pwsh>

# Код 2 — частичная проверка, не успешный native-релиз:
py -3 scripts/release_validate.py
```

Полный ALL_IN_ONE — только для владельца. Клиент получает отдельный клиентский ZIP и txt ключа,
но не проект, Git bundle, owner tools, owner connection, authority и passphrase.
