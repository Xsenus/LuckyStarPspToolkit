System.Runtime 11.0.0.0. Это **альтернативный диагностический host**, не SDK/MSBuild .NET 9.

reference assembly; предупреждений исходного кода runtime-сборок в этом прогоне нет.
Чужой runtime, compiler, DLL/EXE, игровые файлы и файлы шрифтов в поставку не входят.

## Три ошибки подтверждены на старой и новой DLL

Одинаковый измерительный исходник скомпилирован против реально собранных 0.11.0 и 0.12.0.

| Вход | 0.11.0 | 0.12.0 |
|---|---|---|
| No-op и переход внутрь неизменённого сообщения | SCRIPT_JUMP_INSIDE_TEXT | Побайтно идентичная копия |
| Смещение таблицы около UInt32.MaxValue | Необработанный OverflowException | SCRIPT_TABLE_RANGE |
| Нет конца сообщения, корректный checksum начинается словом 0xFFFB | Принят | SCRIPT_GLYPH_EOF |

`reports/script-comparison/probe-*.json` фиксируют результаты двух отдельных процессов.
Переход внутрь действительно изменяемой записи по-прежнему блокируется: библиотека
не угадывает смысл неизвестных команд. Это намеренная граница поддерживаемого переноса.

## Производительность и память

Выполнены одинаковые синтетические сравнения старой и новой DLL на 1024, 4096 и 8192
диалогах, по пять замеров с одним прогревом и `DOTNET_TieredCompilation=0`.
Во всех случаях совпали SHA-256 исходных и выходных сценариев. Подробные числа и
ограничения измерения — в `PERFORMANCE_RU.md`, сырые отчёты — в `reports/script-comparison/`.
Снижение managed allocations в крупнейшем случае: 20621408 → 3335040 байт.
Это не полная память процесса и не проверка производительности настоящей игры.

## Общий протокол

**30 групп пройдено, 0 ошибок, 9 проверок не выполнены.**
PowerShell syntax выполнен; не выполнены native .NET 9 этапы, свежие игровые байты,
удалённый CI и игровая приёмка. Фактические записи находятся в
`reports/validation-summary.json` и соответствуют
конкретному fingerprint исходников, настроек сборки, тестов и runners.
Статус остаётся `partial`, пока не выполнены целевая .NET 9 сборка и игровая приёмка.
Логи защищены SHA-256 для проверки согласованности; это не цифровая подпись или remote attestation.

## Воспроизведение

```powershell
# Штатная проверка, тесты, publish, архив и SHA-256 для Windows:
.\build.cmd --rids win-x64

# Только диагностика на заранее установленном доверенном PowerShell/Roslyn:
python scripts/verify_roslyn.py --pwsh <полный-путь-к-pwsh>

# Общий отчёт: код 2 означает partial, а не успешный native-релиз:
python scripts/release_validate.py
```

## Что не выполнено

Штатные .NET 9 restore/build/self-tests/Roslyn-audit/publish, нативный Windows EXE,
удалённые задания GitHub Actions и запуск игры в PPSSPP/PSP в этой среде не выполнены.
Оригинальный `archive.zip` заказчика, реальные `sc.cpk`, `lt.bin` и чистый ISO здесь
отсутствуют. Согласованность старых customer-хэшей проверена отдельно и **не** выдается
за повторное чтение исходных игровых байтов.

Релиз — проверенный на указанном альтернативном host исходный инженерный комплект,
а не окончательно принятый русификатор двух игр.
