# Надёжность лицензирования 0.15.0

## Шесть сравнительно воспроизведённых дефектов

Один `LicenseScaleFixture.cs` компилируется без изменений против сборок 0.14.0 и 0.15.0.
В режиме `--probe` он наблюдает фактическое поведение, а не выносит вердикт по номеру версии.
Журналы: `reports/license-comparison/014-probe.log` и `015-probe.log` полного комплекта.

| Случай | 0.14.0 | 0.15.0 |
|---|---|---|
| Скачок UTC +сутки, возврат и 7 секунд монотонного времени | Продвижение 0 секунд | Продвижение 7 секунд |
| JSON без обязательного challenge | Принимается, свойство null | JSON_INVALID |
| Явный null вместо обязательного challenge | Принимается | JSON_INVALID |
| Изменение вложенного результата публичного чтения | Меняет базу в памяти | База остаётся неизменной |
| Изменение сохранённого результата транзакции | Меняет базу в памяти | Зафиксированная версия изолирована |
| Перезапуск после отказа истёкшей лицензии с откатом UTC | Доступ мог восстановиться | SERVER_CLOCK_ROLLBACK |

Это дефекты локального API хранилища и времени сервера, а не утверждение, что любой клиент
мог менять базу по сети. Административный доступ и приватные ключи по-прежнему необходимы
для доверенных операций. Смена даты на клиентском ПК не меняет серверный срок.

## Время внутри процесса

На каждом чтении берётся прошедшее монотонное время с последней опорной точки.
Оно прибавляется к последнему принятому UTC, затем учитывается более позднее wall-clock
значение. Новые UTC/timestamp сохраняются вместе под блокировкой. DateTimeOffset сохраняет
доли секунды: частые чтения не отбрасывают накопленное время.
Отрицательный интервал и выход за календарный диапазон отвергаются.

## Время между перезапусками

`server-clock.json` содержит аутентифицированную запись schema/issuer/observedAt.
HMAC-SHA256 вычисляется с отдельным доменом `LSP-SERVER-CLOCK-v1`, отличным от домена базы.
MAC сравнивается в постоянное время; проверяются формат, размер и совпадение издателя.

Перед временным решением authority фиксирует новую наблюдённую UTC-секунду. Внутри той
же секунды повторного flush нет; повторная выдача, проверка или отказ не требуют записи
многомегабайтного снимка licenses.json. При нормальном ходе часов это не более одной небольшой
записи за секунду наблюдений. Искусственные скачки wall clock могут изменить частоту.

Schema 2 не допускает отсутствия checkpoint. При startup observedAt не может быть меньше
LastWriteUtc базы, а текущее UTC — меньше observedAt. Нарушение блокирует запуск; удаление
файла не является поддерживаемым способом восстановления. Первая миграция schema 1 не может
восстановить наблюдения времени, которые старая версия никогда не сохраняла.

При ошибке записи checkpoint новый допуск не подписывается. При ошибке startup закрываются
ключ и process lock: исправленный экземпляр можно открыть повторно без утечки блокировки.

## Изоляция и транзакции

Публичное Read отдаёт отдельный снимок. Change копирует коллекции для callback, валидирует
кандидат и создаёт ещё одну независимую версию для commit. Совместно используются только
неизменяемые строки и immutable leaf records, но не словари установок/лицензий/список аудита.
После успешной атомарной записи публикуется новое состояние. Исключение callback или ошибка
файловой операции сохраняет старое состояние. Сам backend остаётся однопроцессным хранилищем:
эта доработка не превращает JSON-снимок в распределённую СУБД.

Внутренний ReadCommitted имеет более узкий контракт: только чистые запросы authority,
без отдачи коллекций наружу. Сетевой клиент этот callback API не вызывает. Публичный Read
сознательно имеет O(N) стоимость копирования, а не скорость внутреннего heartbeat.

## Прокси и временные отказы

503 с пустым телом или HTML не означает ни отзыва, ни действующей лицензии.
408/429/500/502/503/504 разрешают повтор сетевого обмена только пока жив прежний подписанный
допуск. Watchdog сохраняет исходный deadline. Новый запуск без серверного разрешения
остаётся запрещён; настоящий отказ LICENSE_EXPIRED/REVOKED не превращается в сетевую ошибку.
200 с неверным content-type/телом по-прежнему отвергается как неверный ответ протокола.

## Что не гарантируется

Нет защиты от полного контроля над сервером/root и согласованного отката всей VM/закрытого
каталога. HMAC не шифрует базу и не заменяет резервные копии. Локальный checkpoint не является
внешним доверенным источником времени или аппаратной аттестацией. Flush+rename не выдаётся
за доказанную сохранность при любом отключении питания/сбое файловой системы. Все тесты с
сбоями — воспроизводимые управляемые исключения, не тесты реального отключения диска.
