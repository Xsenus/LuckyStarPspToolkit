# Что показывать заказчику — сценарий демонстрации 0.13.0

## Условия до встречи

Должны быть завершены `build.cmd --rids win-x64` и `python scripts/demo_customer.py --cli ...`. Откройте `build-report.json` и убедитесь, что `compiled`, `testsPassed`, `nativeSmokePassed` (в target) — true. Наличие одного ZIP без этих успешных логов не является подтверждением готовности.

В этой поставке нативный Windows EXE ещё НЕ проверен. Сам C#-сценарий выполнен через Roslyn/PowerShell на .NET 11 preview: все 11 шагов прошли; точные логи находятся в reports/managed-fallback/. Это не заменяет запуск Windows-релиза. При ошибке штатной сборки показывайте код и фактические диагностические результаты, но не обещайте работающую игру.

## Сценарий на синтетическом наборе

| Показ | Действие | Проверяемый результат |
|---|---|---|
| Идентификация | `lsptool.exe version`, затем `--help` | Версия 0.13.0, единый набор команд |
| Самопроверка | `lsptool.exe self-test` | Нулевой код возврата; ошибки видны, а не скрыты |
| Разбор архива | Открыть лог `03-cpk-verify.log` | Повторный разбор синтетического CPK |
| Редактируемый текст | Открыть `translation/script-0000.json` | «Коната», «Привет!», «Да!» находятся в translation-полях |
| Обратная сборка | Открыть лог `06-build.log` и созданный `sc-patched.cpk` | Новый архив и EBOOT size plan созданы отдельно от оригинала |
| Проверка результата | Открыть `reextracted/script-0000.json` | Те же три строки теперь в source-полях повторной выгрузки |
| Безопасный отказ | Открыть `08-reject-control.log` | Вставка `{{GLYPH:FFFF}}` отклонена с exit 3; `MUST_NOT_EXIST.cpk` отсутствует |
| Шрифт | Открыть `synthetic-font.png` и `font-import.json` | Работа LT/BDF на тестовых глифах; это НЕ готовый эстетический шрифт |
| ISO | Открыть `iso-patch.json` | Новая синтетическая ISO, совпадение SHA-256 с независимым эталоном |
| Итог | Открыть `DEMO-REPORT.json` | `passed-synthetic-demo`; `SYNTHETIC`; `gameRuntimeVerified: false` |

Демонстрация автоматизирована и сама проверяет все эти условия. Не нужно вручную писать «PASS» в отчёт. Синтетические рисунки глифов служат для проверки битов и метаданных; их нельзя представлять как читабельный готовый русский шрифт.

## Что говорить

«Это предварительная инженерная версия инструмента. На тестовом наборе показан цикл извлечения текста, изменения, обратной сборки и повторного чтения. Отдельно проверяются отказ при опасных служебных кодах и перестройка образа. Реальная совместимость Lucky Star проверяется следующим этапом на ваших оригинальных ресурсах».

Не говорите «всё идеально», «обе игры полностью готовы», «100% всех сцен проверено», «PSP точно работает» или «здесь запущена игра», когда показан только JSON/синтетический ISO.

## Отдельная игровая приёмка

Когда доступны `sc.cpk`, `lt.bin`, исходный EBOOT, проверенная карта и ISO:

1. Зафиксировать хэши, ревизию и оригинал. Сделать no-change round-trip архивов/шрифта.
2. Выбрать короткую реплику, длинную реплику, имя, вариант ответа, Ё/ё, знаки препинания и переносы. Проверить все затронутые глифы по карте, а не только наличие букв в текстовом файле.
3. Пересобрать CPK, шрифт, EBOOT с таблицей размеров и heap, затем отдельный ISO. Не модифицировать чистый образ на месте.
4. Запустить чистую и изменённую сборки в одной версии PPSSPP с одинаковыми настройками. Проверить загрузку, вывод, журнал, выборы, сохранение/загрузку и переходы сцен.
5. Повторить на реальной PSP, если её поддержка входит в договорённость. Показать модель/прошивку/условия запуска и фактический результат.
6. Записать пройденные сцены, проблемные строки, результаты сохранений. Прохождение нескольких сцен не означает проверку всей игры.

По Net Idol Meister приёмка отдельная: профиль EBOOT и бинарные ограничения этой игры нельзя автоматически перенести с ULJM05752.

## Что передавать

Заказчику после успешной нативной сборки: ZIP win-x64, SHA-256, короткую инструкцию, подтверждённые логи демонстрации и список ограничений. Исходный комплект — отдельно по условиям работы. Не отправляйте полные оригинальные игровые файлы в публичный репозиторий.

## Дополнение 0.13.0: сохранность CPK

На синтетическом наборе покажите `cpk-verify`: без правок общий SHA-256 должен
совпасть. После правки повторно извлеките выбранный файл и сравните его содержимое.
Покажите TEST_REPORT_RU.md и CPK_PERFORMANCE_RU.md: неизвестные metadata сохраняются
при переносе size-class либо сборка останавливается. Это проверка инструмента,
не демонстрация перевода настоящей игры; оригинальный sc.cpk пока недоступен.
