# Производительность сценариев — 0.12.0

## Что измерено

22 сентября 2026 года выполнен сравнительный микротест настоящих C#-сборок
0.11.0 и 0.12.0 в одном окружении: PowerShell 7.7.0-preview.4,
.NET 11.0.0-preview.6.26359.118, Roslyn, режим оптимизации Release, C# 13.
Это **не штатная .NET 9 SDK сборка и не замер Windows или настоящей игры**.

Один и тот же исходник `ScriptScaleFixture.cs` скомпилирован отдельно против
каждой версии `LuckyStarPspToolkit.Formats.dll`. В каждой группе создан синтетический
сценарий RGO; половина сообщений увеличивается с 8 до 10 глифов. На диалог есть
переход к началу и к терминатору. Перед пятью замерами выполнен один прогрев.
Приведены медианы. Перед замером вызывается сборка мусора. В обоих процессах
явно задано `DOTNET_TieredCompilation=0`, чтобы исключить смену JIT-tier во время
коротких серий. Это настройка **микротеста**, не изменение обычной конфигурации приложения.
Время охватывает `Build`, пересчёт указателей, checksum и повторный разбор результата;
создание входного объекта и массивов перевода не входит.

| Диалогов / целей / правок | 0.11.0, мс | 0.12.0, мс | Новые managed allocations 0.11.0, байт | 0.12.0, байт |
|---|---:|---:|---:|---:|
| 1024 / 2049 / 512 | 33.2558 | 0.6377 | 2,975,744 | 635,704 |
| 4096 / 8193 / 2048 | 612.9700 | 1.9449 | 10,518,672 | 1,794,920 |
| 8192 / 16385 / 4096 | 1887.0032 | 3.7401 | 20,621,408 | 3,335,040 |

В крупнейшем случае новые управляемые выделения снизились примерно в 6,18 раза
(на 83,83%). Это `GC.GetAllocatedBytesForCurrentThread`, **не** RSS, не вся память
процесса и не гарантия максимального потребления памяти. Время — наблюдение этой
конкретной серии с отключённой tiered compilation; его нельзя переносить на другие
сценарии, машины или обещать как ускорение всей утилиты.

SHA-256 входов и результатов совпали у обеих версий во всех трёх группах.
Для 8192 диалогов:

```text
source: 477ddcfd013bf8c13ef3caac6d93448228fcc43fc76ffa66ef9fae792473e2af
output: 64e1df71b316aa94c7b5563801d9d98e2ca9ab5ee9d865f80faad7649661c56c
```

В полном комплекте исходные пять замеров, контрольные суммы DLL и хэши измерительного
кода находятся в `reports/script-comparison/`. Эти DLL в комплект **не входят**.

## Почему изменился алгоритм

Раньше каждый запрос смещения последовательно проходил интервалы замен.
Теперь `ScriptOffsetMap` строит индекс один раз и выполняет двоичный поиск:
для `J` целей и `M` интервалов поиск меняется с O(J×M) на O(J×log M).
Сортировка текстовых записей остаётся O(N×log N), само копирование и checksum — O(B).
Указанные сложности относятся к алгоритму, а не к измеренному времени всей игры.

При сборке сериализуются только действительно изменённые записи. Буфер результата
выделяется один раз после проверки итоговой длины; промежуточных `List<byte>` и
отдельных копий каждого неизменённого фрагмента больше нет. Верификация всё ещё
разбирает результат и создаёт собственный снимок: она намеренно не отключена ради скорости.

Без изменений возвращается отдельная побайтно идентичная копия корректного сценария,
включая padding. Неизменённые текстовые записи больше не объявляются заменами.

## Как воспроизвести на целевой .NET 9

После обычной успешной сборки:

```powershell
$env:DOTNET_TieredCompilation = '0'
dotnet run --project tests/LuckyStarPspToolkit.Formats.SelfTests -c Release --no-build -- --script-benchmark
Remove-Item Env:DOTNET_TieredCompilation
```

Для сравнения двух версий повторите одну и ту же нагрузку на обеих сборках и сохраняйте
отдельные отчёты. Для полноценного эксплуатационного замера дополнительно выполните
серии с настройками JIT по умолчанию, на настоящих файлах, с прогревом и большим числом
повторений. Ни одна такая серия в текущем релизе не выдается за выполненную.

Для разработчика с уже установленным доверенным PowerShell/Roslyn имеется диагностический
runner; он ничего не скачивает и не выпускает принимаемый бинарный релиз:

```powershell
$env:DOTNET_TieredCompilation = '0'
./scripts/benchmark_scripts.ps1 -Root . -ReferenceDirectory <папка-с-Formats.dll> -Out artifacts/bench-run-unique
# -Probe вместо измерений воспроизводит три исправленных дефекта.
```

`-Out` должен быть новым каталогом внутри `artifacts`. Для каждой версии нужен отдельный
процесс, отдельный каталог и соответствующая ей DLL. В каждой серии проверяется SHA-256
результата. Runner фиксирует реальную версию и среду; .NET 11 Preview не маркируется как .NET 9.

## Другие показатели

Проверка нового лимита размера отклонила прямую замену размером 400000 байт до создания
сериализованного текста и результата: на этом host выделено 1104 managed-байта
(уже переданный массив в число не входит). Это один regression case, не общий предел памяти.

Регрессия AES-CMAC из 0.11.0 сохранена: на сообщении 4 МиБ после прогрева пула снова
измерено 1392 managed-байта; исходный массив, начальное выделение пула, нативная
криптография и RSS в этот счётчик не входят.
