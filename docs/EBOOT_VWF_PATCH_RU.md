# Патч EBOOT для кириллицы и переменной ширины

## Назначение

Профиль `rgo-uljm05752-russian-vwf-v1` предназначен только для подтверждённой японской ревизии:

```text
Игра:                 Lucky Star: Ryouou Gakuen Outousai Portable
DISC_ID:              ULJM05752
Encrypted EBOOT SHA:  4a22c50c0a6ad6249dd1d9ab015d559b19b4acd79daf892a6f29a58648b834f0
Decrypted ELF SHA:    3e6c1c2f7136a69cecda4f39835c3454b739e23e89e862fe17462cdf915581d8
Full VWF ELF SHA:     0a2ce9212c3335e17fad28d457b0caf7f25bc1b046707e0da994ee8437f7244f
```

Профиль содержит **133 точные 32-битные MIPS-замены**. Для каждой точки известны смещение, исходное слово и новое слово. Запись выполняется только тогда, когда текущее значение совпадает либо с подтверждённым оригиналом, либо с уже применённой заменой.

## Группы

```text
vwf-core         66  ядро переменной ширины
message-layout    7  окно сообщения и автоматические переносы
speaker-layout   50  поле имени говорящего и его лимиты
choice-layout     3  варианты ответа
name-layout       7  имя игрока и экран сохранений
```

Псевдоним `russian-text` выбирает все группы, `core-only` — только `vwf-core`.

## Просмотр состояния

```powershell
lsptool eboot-vwf-groups

lsptool eboot-vwf-inspect EBOOT.BIN `
  --json eboot-vwf-inspection.json
```

Инспектор распознаёт четыре безопасных состояния:

1. точный исходный EBOOT;
2. известный частично применённый профиль;
3. полный канонический VWF-патч;
4. известную линию происхождения с корректно изменённой таблицей сценариев и script heap.

Любое слово, не совпадающее ни с оригиналом, ни с известной заменой, блокирует операцию. Изменение произвольного байта вне разрешённых динамических областей также нарушает канонический SHA-256 и отклоняется.

`verify-eboot` возвращает успешный статус для чистого проверенного EBOOT, точного полного VWF и полного VWF с согласованными size table/heap. Для действительно частичного профиля возвращается отдельный статус incomplete.

## Применение VWF

```powershell
lsptool eboot-vwf-apply EBOOT.BIN EBOOT.VWF.ELF `
  --groups russian-text `
  --json eboot-vwf-result.json
```

Команда идемпотентна: повторное применение к тому же ELF не меняет ни одного байта. Частично применённый профиль можно безопасно дополнить оставшимися группами.

Выход — **расшифрованный ELF**, а не заново зашифрованный retail PRX. Его нельзя считать универсальным подписанным `EBOOT.BIN`. Проверка выполняется в PPSSPP и на PSP с подходящей средой запуска homebrew/decrypted executables. Исходный зашифрованный файл никогда не изменяется на месте.

## Совместная сборка с новым `sc.cpk`

`workspace-build` создаёт `eboot-size-plan.json`. VWF и план размера следует применять одной командой к чистому исходному EBOOT:

```powershell
lsptool eboot-build EBOOT.BIN EBOOT.TRANSLATED.ELF `
  --size-plan eboot-size-plan.json `
  --groups russian-text `
  --json eboot-build.json
```

Совместная операция разрешена только для точного исходного ELF. Это не позволяет случайно наложить план повторно на частично изменённый файл.

Перед записью проверяется, что области 133 MIPS-слов не пересекаются с:

```text
таблица размеров сценариев: 0x10319E, 11 строк по 4 байта
script heap LUI:            0x015B54
script heap ADDIU:          0x015B58
```

После применения плана сравнивается каждый изменённый байт. Разрешены изменения только в таблице размеров и двух инструкциях heap. Затем итог повторно проходит полную проверку линии происхождения.

## Script heap

Исходный буфер сценария задаётся парой инструкций:

```text
0x015B54: lui   a0, 0x0023
0x015B58: addiu a0, a0, 0x6000
```

Это даёт `0x236000`, то есть 2 318 336 байт. Требуемый размер вычисляется как:

```text
max(0x236000, максимальный размер одного сценария по таблице EBOOT)
```

Если сценарий становится больше, утилита пересобирает пару `lui/addiu` с учётом знакового 16-битного immediate (`%hi/%lo`). Например, 1200 блоков по 2048 байт требуют `0x258000`:

```text
lui   a0, 0x0026
addiu a0, a0, 0x8000
```

`0x8000` интерпретируется как отрицательное знаковое значение, поэтому верхняя половина должна быть округлена вверх. Простое разбиение числа на старшие и младшие 16 бит здесь неверно.

Инструмент отклоняет:

- другую пару регистров или opcodes;
- heap меньше требуемого;
- произвольный ранее увеличенный heap, не равный текущему расчёту;
- нулевой размер сценария;
- повреждённую накопительную таблицу;
- переполнение 16-битных полей таблицы.

## Проверенная база

Независимый Python-oracle, не исполняющий C#-код, выполнил на файле заказчика:

- расшифровку PRX Type 2;
- проверку всех 133 исходных слов;
- применение полного набора;
- получение канонического SHA-256 полного ELF;
- идемпотентное повторное применение;
- завершение частичного профиля;
- сохранение корректно изменённой таблицы размеров;
- увеличение heap до 2 457 600 байт для сценария из 1200 блоков;
- отказ при таблице без соответствующего heap;
- отказ при повреждении MIPS-слова, heap-инструкции и постороннего байта.

Это подтверждает бинарную трансформацию перед компиляцией C#. Финальная игровая совместимость всё равно требует настоящих `sc.cpk`, `lt.bin`, чистого ISO и запуска в PPSSPP/на PSP.
