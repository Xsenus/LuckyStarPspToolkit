# React-панель владельца · 0.18.0

Это owner-only компонент. Заказчик получает только клиентский ZIP и ключ, но не исходники,
сервер, админку, каталог authority, MFA enrollment или Git bundle. Развёртывание предполагается
в приватном репозитории. Ключи доступа, исходные игры и шрифты в поставке отсутствуют.

## Возможности

Панель показывает лицензии, статус, срок, установки, поиск и страницы по 25 записей.
Можно выдавать часы/дни/годы/бессрочный доступ с отсчётом от выдачи или первой активации;
продлевать, приостанавливать, возобновлять и окончательно отзывать лицензии;
освобождать слот установки, смотреть последние 500 событий журнала.
Раздел резерва включает общий выключатель, выдачу 1–168 часов для активированной установки,
список допусков с поколениями и индивидуальный отзыв. Подробности — RESERVE_ACCESS_RU.md.

Вход: пароль + TOTP. Поддерживаются восемь одноразовых кодов восстановления **второго фактора**.
Они не заменяют пароль и не дают пользователю программы мастер-доступ. Сейчас поддерживается
одна учётная запись владельца, без многопользовательских ролей и без публичной регистрации.

## Сборка владельцем

Нужны .NET 9 SDK, Python 3.11+ с validation/requirements.txt и Node.js 22+.
Из папки project:

```powershell
py -3 -m pip install -r validation/requirements.txt
node --version
node web/license-admin/test.mjs
node web/license-admin/build.mjs
py -3 scripts/build_license_owner.py --rids linux-x64,win-x64
```

При успехе owner ZIP находится в `artifacts/owner-releases/0.18.0/`.
Внутри каждой платформы `server/`, `admin/`, `web/`, `docs/`, `deploy/`.
Frontend использует закреплённые MIT production-модули React с проверкой SHA-256;
Node нужен при сборке, но **не при работе** сервера. CDN, npm install и Vite runtime не нужны.
Подробное происхождение React записано в web/license-admin/vendor-manifest.json.

Сборка клиентского приложения остаётся отдельной:

```powershell
.\build.cmd --rids win-x64 --license-trust C:\LspOwner\client-trust.json
```

Админский токен и приватный ключ подписи не попадают в браузер и клиентские файлы.
Клиент не принимает изменённый адрес/ключ издателя из случайного соседнего JSON.

## Новый сервер или обновление

Для нового сервера сначала выполните обычный `init` из LICENSE_OWNER_RU.md.
Для уже работающего 0.15.0 новый `init` **не выполняйте**: issuer, ключи и лицензии сохраняются.
Остановите службу и сделайте закрытую согласованную копию authority и отдельно master.pass.
Схема базы автоматически меняется с 2 на 3. `server-clock.json` остаётся обязательным.
До нового запуска создайте веб-учётную запись командой из следующего раздела.

Замените `/opt/lsptool-license/server`, `/opt/lsptool-license/admin` и добавьте `web` из owner-релиза.
Эти каталоги должен изменять только root/оператор развёртывания, не HTTP-процесс.
Исходный `lsptool-license.service` без web-root остаётся вариантом сервера без браузерной панели.
Файл `lsptool-license-web.service` — **альтернативный шаблон той же службы**, не второй процесс authority.

## Создать владельца (сервер остановлен)

Пример для уже установленного Linux owner-релиза:

```bash
sudo -u lsptool-license /opt/lsptool-license/admin/lsp-license-admin web-init \
  --data /var/lib/lsptool-license/authority \
  --username owner \
  --origin https://admin.example.com \
  --out /var/lib/lsptool-license/web-enrollment.json
```

Замените example-домен своим. Origin — строго `https://host[:port]`, **без завершающего /**,
пути, wildcard или query. В интерактивном скрытом вводе задайте **новый пароль входа в админку**,
16–256 символов, не пароль приватного ключа издателя. Можно передать --password-file с защищённым
отдельным файлом вместо интерактивного ввода. Не передавайте пароль обычным аргументом команды.

Приватный enrollment содержит Base32 TOTP seed, otpauth URI и 8 recovery-кодов.
Импортируйте seed в приложение-аутентификатор, а recovery-коды сохраните в закрытом менеджере паролей.
Это не файл клиента и не веб-ресурс. Не копируйте его в web/, Git или общий чат.
Пароль в enrollment не записывается. После безопасного сохранения у владельца удалите его с VPS.

Если путь --out уже существует или недоступен, учётная запись не создаётся. Повторная инициализация
существующего владельца запрещена. Сбой доставки bootstrap не оставляет скрытую рабочую учётную запись.

## Домен, HTTPS и служба

Три порта остаются только на 127.0.0.1:

| Порт | Назначение | Публикация |
|---|---|---|
| 17840 | Активация/проверка клиента | Только HTTPS licenses.example.com через Nginx |
| 17841 | Старое административное bearer API | **Не публиковать**; SSH-туннель владельца |
| 17842 | Browser backend с cookie/MFA/CSRF | HTTPS admin.example.com |

Существующий deploy/licensing/nginx.conf обслуживает клиентский API.
Для панели установите отдельный deploy/licensing/nginx-admin.conf в nginx http context,
а deploy/licensing/lsp-admin-proxy.conf — в `/etc/nginx/snippets/lsp-admin-proxy.conf`.
Замените домен и пути **существующих действительных TLS-сертификатов**. Не открывайте 17840–17842
через firewall. Snippet обязан перезаписывать X-Real-IP, не доверять его значению от внешнего клиента.

В ExecStart существующей службы добавьте:

```text
--web-root /opt/lsptool-license/web --web-port 17842
```

Порядок завершения настройки:

```bash
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl restart lsptool-license
sudo systemctl reload nginx
sudo systemctl status lsptool-license --no-pager
```

Адрес входа после настройки: `https://admin.example.com`. Не используйте localhost или IP вместо
заданного production-origin; Secure cookie/Origin тогда намеренно не работают.
Не включайте --development-loopback на production. Этот режим только для явно локальных тестов.

## Выдать обычный ключ через браузер

Откройте «Выдать ключ», задайте клиента, длительность, начало отсчёта и лимит установок.
Перед отправкой автоматически скачивается **закрытая квитанция владельца** с одним ID и ключом.
Если ответ потерян, повторное нажатие использует тот же запрос, а не выдаёт второй ключ.
После подтверждения скачайте `access-key.txt` кнопкой «Скачать ключ клиенту».
Именно этот TXT и клиентский ZIP отправляются заказчику. В базе сохраняется HMAC, а не исходный ключ;
позднее «показать полный старый ключ» невозможно без вашей квитанции.

При закрытии вкладки без ответа квитанцию можно загрузить кнопкой «Повторить выдачу из квитанции».
Для других мутаций ID сохраняется только в текущей вкладке на время неопределённого результата.
После перезагрузки вкладки сначала проверьте список/журнал, прежде чем повторять продление.
Сетевая ошибка никогда не считается подтверждением выдачи или продления.

## Защита входа и сессий

Пароль: PBKDF2-SHA256 600000 итераций с независимой случайной солью. TOTP SHA-1, 6 цифр,
30 секунд, окно ±1 шаг; уже принятый шаг не принимается повторно даже после рестарта.
Recovery code расходуется на сервере до выдачи сессии и всё равно требует правильного пароля.
TOTP seed хранится в **приватном** account-файле с контролем целостности, не в открытом web-root;
HMAC не шифрует seed. Полный backup authority должен быть закрытым/зашифрованным средствами владельца.

Сессия: HttpOnly/Secure/SameSite=Strict cookie с host-prefix, 15 минут без активности и максимум 8 часов.
Cookie и CSRF — разные случайные значения. Мутации требуют точного Origin и CSRF.
Высокорисковые действия (резерв, бессрочная выдача, отзыв, сброс установки) после пяти минут требуют
нового пароля и нового второго фактора. После подтверждения действие запускается повторным кликом.
После выхода или рестарта старые сессии не действуют. Автоматический опрос панели не поддерживает
сессию бесконечно: обновление выполняется по действию пользователя.

## Восстановление владельца

Если утрачен TOTP, используйте пароль + один recovery-код. При повторном входе этот код уже не работает.
Если утрачены пароль и/или все вторые факторы, нужен административный SSH-доступ к VPS:
остановите службу, сохраните закрытую копию account-файла, перенесите **только web-account.json**
из authority в защищённый карантин и снова выполните web-init. Не трогайте authority.json, базу,
server-clock.json, signing key или установки клиентов. Старые сессии потеряны при рестарте.
Это локальная операция владельца, не HTTP-сброс пароля без проверки.

## Приёмка перед внешним доступом

Проверьте production HTTPS, cookie Secure/HttpOnly/SameSite в браузере, блокировку запросов без CSRF,
выход/истечение сессии, вход с новым TOTP, одноразовость recovery и обновление сервера с сохранением
лицензий. Реальный VPS/DNS/TLS и Windows CNG здесь не развёрнуты за владельца.

## Изменения 0.18.0

См. [Резерв и сессии](RESERVE_SESSION_HARDENING_RU.md). Добавлена вкладка «Сессии владельца» с завершением других входов. Обновляйте backend и web одновременно. При переходе с **0.16.0** не повторяйте web-init: существующие пароль, TOTP и recovery-коды сохраняются; схема 3 не меняется.

## Страницы и обновление 0.17.0 → 0.18.0

Теперь фильтрация и страницы выполняются на сервере; полный список устройств не
передаётся при открытии списка. История резервов доступна за пределами 200 записей.
Карточка лицензии грузится отдельно. Используйте «Применить фильтры» после ввода поиска,
затем «Назад/Далее». При изменении базы или истечении двухминутного cursor-снимка панель
покажет уведомление и вернётся к первой странице. Верхние счётчики относятся ко всей базе.

Для обновления 0.17.0 не нужен новый init, web-owner-init или миграция схемы. Остановите
сервер, сделайте закрытую копию authority+server-clock.json и замените server/admin/web
вместе. Войдите заново. Основные лицензии и установленный клиент остаются совместимыми.
Полные правила, API и пределы: [ADMIN_QUERIES_RU.md](ADMIN_QUERIES_RU.md).
